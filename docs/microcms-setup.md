# microCMS セットアップ手順書

ドッグガーデンシュシュ公式サイトが参照する microCMS の設定内容をまとめたものです。
**この通りに作れば、コード側は一切変更せずに接続できます。**

作成するAPIは **`puppies`（仔犬）** と **`parents`（親犬）** と **`voices`（お客様の声）** の3つです。

> 里親募集ページは個別の犬情報を掲載せず公式LINE誘導のみとする方針になったため、
> `rehoming` API は **作成不要** です。

---

## 0. 全体像

| API | 形式 | 用途 | 参照しているページ |
| --- | --- | --- | --- |
| `puppies` | リスト形式 | 仔犬1頭ぶんの情報 | `/puppies`、`/puppies/[id]`、TOPの犬種カード |
| `parents` | リスト形式 | 親犬（父犬・母犬）の情報。`puppies` から参照する | `/puppies/[id]` の「両親の情報」 |
| `voices` | リスト形式 | お客様の声 | `/voice`、TOPの THANK YOU セクション |

**作成する順番が重要です。** `puppies` は `parents` を参照するため、
**必ず `parents` → `puppies` → `voices` の順**で作成してください。

---

## 1. サービスの作成

1. [microCMS](https://microcms.io/) にログインし、サービスを新規作成します
2. **サービスID** を決めます（例: `dog-garden-chouchou`）
   - 管理画面のURL `https://<サービスID>.microcms.io/` の `<サービスID>` の部分です
   - これがそのまま環境変数 `MICROCMS_SERVICE_DOMAIN` の値になります
   - **後から変更できない**ため、ここで確定させてください

---

## 2. `parents` API（親犬）

「APIを作成」→ **リスト形式** を選択。

- API名: `親犬`
- エンドポイント: **`parents`**

### フィールド定義

| フィールドID | 表示名 | 種類 | 必須 | 補足 |
| --- | --- | --- | --- | --- |
| `image` | 写真 | 複数画像 | ○ | **1枚だけ**登録してください（コードは1枚目のみ使用） |
| `name` | 名前 | テキストフィールド | ○ | 例: `モモ` |
| `breed` | 犬種 | テキストフィールド | ○ | 例: `マルチーズ` |
| `sex` | 性別 | セレクトフィールド | ○ | 選択肢は `男の子` / `女の子` の2つ。**複数選択はオフ** |
| `birthday` | 誕生日 | 日時 | ○ | |
| `color` | 毛色 | テキストフィールド | ○ | 例: `ホワイト` |
| `weight` | 体重 | 数値 | ○ | 単位は kg。サイト上では `3.2kg` のように表示されます |

> **`sex` の選択肢の文字列は表示にそのまま使われます。**
> `オス` / `メス` にすると画面にもそう出ます。`男の子` / `女の子` で統一してください。

---

## 3. `puppies` API（仔犬）

「APIを作成」→ **リスト形式** を選択。

- API名: `仔犬`
- エンドポイント: **`puppies`**

### フィールド定義

| フィールドID | 表示名 | 種類 | 必須 | 補足 |
| --- | --- | --- | --- | --- |
| `images` | 写真 | 複数画像 | ○ | **1枚目がメイン画像**、2枚目以降がサムネイルになります |
| `breed` | 犬種 | テキストフィールド | ○ | **TOPの犬種カードの絞り込みキーになるため表記ゆれ厳禁**（下記参照） |
| `breed_explanation` | 犬種の補足説明 | テキストエリア | | 空欄なら非表示 |
| `sex` | 性別 | セレクトフィールド | ○ | 選択肢 `男の子` / `女の子`。複数選択はオフ |
| `birthday` | 誕生日 | 日時 | ○ | 「生後◯ヶ月」は誕生日から自動計算されます |
| `color` | 毛色 | テキストフィールド | ○ | |
| `expected_weight` | 成犬時予想体重 | 数値 | | 単位 kg。`3kg以下` と表示されます |
| `expected_height` | 成犬時予想体高 | 数値 | | 単位 cm。`25cm以下` と表示されます |
| `price` | 価格 | 数値 | | **税込・円**で入力。空欄なら `応相談` と表示されます |
| `message` | ブリーダーからのメッセージ | テキストエリア | ○ | |
| `mother` | 母犬 | コンテンツ参照 → `parents` | | |
| `father` | 父犬 | コンテンツ参照 → `parents` | | |
| `status` | ステータス | セレクトフィールド | | 選択肢 `商談中` / `成約済み`。**未選択＝募集中**。複数選択はオフ |

### `breed`（犬種）の表記ルール — ここが一番の注意点

TOPページの犬種カードは `breed` の**文字列完全一致**で仔犬を絞り込みます。
`トイプードル` と `トイ・プードル` は別物として扱われ、カードに出てこなくなります。

現在サイトが想定している表記は以下の5つです。この通りに統一してください。

- `マルチーズ`
- `チワワ`
- `トイプードル`
- `ビションフリーゼ`
- `ミックス`

> 犬種を追加・変更する場合は `app/_components/puppies/index.tsx` の犬種リストも
> 合わせて更新が必要です。ご連絡ください。

### 価格の扱い

`price` は構造化データ（Google向けの商品情報）にも出力されます。
価格を非公開にしたい場合は空欄にしてください。空欄なら構造化データにも価格が出ません。

## 4. `voices` API（お客様の声）

「APIを作成」→ **リスト形式** を選択。

- API名: `お客様の声`
- エンドポイント: **`voices`**

### フィールド定義

| フィールドID | 表示名 | 種類 | 必須 | 補足 |
| --- | --- | --- | --- | --- |
| `image` | 写真 | 画像 | | **単一画像**（`puppies` と違い複数画像ではありません） |
| `title` | 見出し | テキストフィールド | ○ | 例: `福岡市 T様宅　マルチーズ　〇〇ちゃん` |
| `body` | 本文 | テキストエリア | ○ | |

---

## 5. APIキーの発行と権限設定

「サービス設定」→「APIキー」から発行します。

### このサイトに設定するキーの権限

セキュリティ上、**GET のみ**に絞ってください。

| 権限 | 設定 | 理由 |
| --- | --- | --- |
| GET | **ON** | サイト表示に必要 |
| POST / PUT / PATCH / DELETE | **すべてOFF** | サイト側は書き込みを一切行いません。ONにするとキー漏洩時にコンテンツを改ざんされます |
| 下書きコンテンツの取得 | OFF | プレビュー機能を使う場合のみON |
| 公開終了コンテンツの取得 | OFF | |

> microCMS公式ドキュメントでも、書き込み権限つきキーの露出リスクと、
> 読み取り／書き込みキーの分離が推奨されています。
> 参照: [APIキー（APIの認証と権限管理）](https://document.microcms.io/content-api/x-microcms-api-key)

### 重要：現在お預かりしているキーについて

チャット上でAPIキーをお送りいただいたため、**公開前に必ずキーを再発行（ローテーション）してください。**
チャットの履歴に残っているキーは漏洩したものとして扱うのが安全です。

## 6. 環境変数の設定

### ローカル開発（`.env.local`）

リポジトリ直下に `.env.local` を作成します（`.gitignore` 済みなのでコミットされません）。

```bash
# サイトURL（本番の独自ドメイン。末尾スラッシュなし）
NEXT_PUBLIC_SITE_URL=https://example.com

# microCMS
MICROCMS_SERVICE_DOMAIN=dog-garden-chouchou   # ← サービスIDのみ。.microcms.io は不要
MICROCMS_API_KEY=（発行したGET専用キー）

# Google Analytics 4（任意。未設定ならタグを出力しません）
NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX
```

### 本番（Vercel）

Vercel の Project → Settings → Environment Variables に同じ4つを登録します。

| 変数名 | 対象環境 | 備考 |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Production / Preview | **Production には独自ドメインを入れる。** canonical・sitemap・OGPすべてがこの値を使います |
| `MICROCMS_SERVICE_DOMAIN` | 全環境 | |
| `MICROCMS_API_KEY` | 全環境 | |
| `NEXT_PUBLIC_GA_ID` | Production のみ | Preview環境のアクセスを計測に混ぜないため |

> `NEXT_PUBLIC_` 付きの変数は**ビルド時に埋め込まれます**。
> 値を変更したら再デプロイが必要です。

---

## 7. 未接続時の挙動（今の状態）

`MICROCMS_SERVICE_DOMAIN` か `MICROCMS_API_KEY` のどちらかが空の場合、
サイトは `app/_data/mockPuppies.ts` / `mockVoices.ts` のダミーデータを表示します
（`app/_lib/microcms/client.ts` の `isMicroCMSConfigured`）。

環境変数を設定すれば自動的に本番データに切り替わるため、コードの変更は不要です。
またAPI取得が失敗した場合もモックにフォールバックし、サイトが落ちないようにしています。

---

## 8. 更新がサイトに反映されるまでの時間

ISR（Incremental Static Regeneration）で **1時間** に設定しています
（`app/_config/isr.ts` の `defaultRevalidateTime = 3600`）。

microCMSでコンテンツを更新してから最大1時間でサイトに反映されます。

### 即時反映したい場合（任意・推奨）

microCMSのWebhookでVercelの再デプロイを叩く設定を入れると、更新が即座に反映されます。

1. Vercel → Project → Settings → Git → **Deploy Hooks** でフックURLを作成
2. microCMS → 各API → 「API設定」→「Webhook」→「カスタム通知」
3. 手順1のURLを登録し、通知タイミングを「コンテンツの公開・更新・削除時」に設定
4. `puppies` / `parents` / `voices` の3つすべてに設定

## 9. 作成後のチェックリスト

- [ ] `parents` → `puppies` → `voices` の順に作成した
- [ ] `puppies.mother` / `puppies.father` が `parents` へのコンテンツ参照になっている
- [ ] `sex` の選択肢が `男の子` / `女の子`、`status` が `商談中` / `成約済み`
- [ ] `sex` と `status` の「複数選択」がオフになっている
- [ ] `breed` の表記が5犬種で統一されている
- [ ] APIキーの権限が **GETのみ**
- [ ] チャットで共有したAPIキーを再発行した
- [ ] `.env.local` と Vercel の環境変数を設定した
- [ ] テストコンテンツを1件公開し、`/puppies` に表示されることを確認した
