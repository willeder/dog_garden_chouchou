# Google Analytics 4 計測設計

測定ID: `G-PWN1SW9F4E`
最終更新: 2026年8月16日

---

## 0. このサイトで測りたいこと

このサイトの目的は**公式LINEの友だち追加**です。それ以外の指標は、そこへ至る過程を説明するためのものです。

```
検索・SNS → サイト来訪 → 仔犬を見る → LINE友だち追加
                              ↑ここで落ちてないか？
```

そのため計測は次の3階層で設計しています。

| 階層 | 何を測るか | 主なイベント |
| --- | --- | --- |
| ゴール | LINE友だち追加ボタンが押されたか | `line_add_friend_click` |
| 手前の行動 | どの仔犬が見られ、どこから問い合わせ導線に進んだか | `view_puppy_detail` / `cta_click` |
| 探し方 | どの犬種が探され、どの質問が読まれたか | `filter_breed` / `faq_open` / `puppy_list_paginate` |

## 1. 実装しているイベント一覧

すべて実機（Chromium）でクリック・遷移を再現し、`dataLayer` に正しい値が積まれることを確認済みです。

### `line_add_friend_click`（最重要）

公式LINEの友だち追加ボタンのクリック。**これをGA4の「キーイベント」に設定してください**（手順は §3）。

| パラメータ | 値の例 | 意味 |
| --- | --- | --- |
| `link_location` | `contact_page` / `adoption_page` / `visit_page` / `top_contact` / `puppy_detail_bottom` / `puppy_list_bottom` | どのページの導線から押されたか |

これにより「LINE追加の何割が仔犬詳細ページ経由か」が分かります。

### `view_puppy_detail`

仔犬詳細ページの閲覧。**どの犬種に需要があるかが数字で分かります。**

| パラメータ | 値の例 |
| --- | --- |
| `puppy_id` | `sample-1`（microCMSのコンテンツID） |
| `breed` | `マルチーズ` |
| `sex` | `男の子` |
| `status` | `募集中` / `商談中` / `成約済み` |
| `price` | `230000`（成約済みの子は送信しません。画面表示と揃えるため） |

### `cta_click`

サイト内の導線ボタンのクリック。

| パラメータ | 値の例 |
| --- | --- |
| `cta_label` | `LINEで見学・お問い合わせ` / `READ MORE` / `見学のお申し込みはこちらから` |
| `link_location` | `puppy_detail` / `top_adoption` / `top_links` / `warranty_page` / `faq_page` |
| `to` | `/contact` / `/visit` / `/faq` |

### `social_click`

| パラメータ | 値の例 |
| --- | --- |
| `social_network` | `instagram` / `tiktok` |
| `link_location` | `footer` / `top_instagram_section` / `top_instagram_card` |

TOPのInstagram投稿カード3枚も個別に計測しています。「カードは押されるがボタンは押されない」といった差が見えます。

### `filter_breed`

仔犬一覧の犬種チップ。**サイト内検索の代わりになる指標**で、「探されているが在庫がない犬種」を見つけられます。

| パラメータ | 値の例 |
| --- | --- |
| `breed` | `トイプードル` / `トイプードル（解除）` |
| `link_location` | `puppy_list` |

### `puppy_list_paginate`

| パラメータ | 値の例 |
| --- | --- |
| `page` | `2` |

2ページ目以降がほとんど見られていなければ、1ページの表示件数を増やす判断材料になります。

### `faq_open`

FAQアコーディオンを**開いたときだけ**送ります（閉じる操作は送りません）。

| パラメータ | 値の例 |
| --- | --- |
| `faq_question` | `お迎え時に必要なものは何ですか？` |

よく開かれる質問が分かるので、その内容を上位に出す・別ページ化するといった判断ができます。

### `page_view`

App Router（Next.js）はページ遷移をJavaScriptで行うため、標準のgtag設定のままだと
**遷移前のページタイトルが送られてしまう**という既知の問題があります。

そのため `send_page_view: false` にしたうえで、遷移完了後に自前で `page_view` を送っています
（`app/_components/GoogleAnalytics.tsx`）。ページタイトルとURLが必ず一致します。

> 注: 犬種フィルタはURLに `?breed=マルチーズ` を付けるため、フィルタ操作のたびに
> `page_view` が1件増えます。これは「絞り込み後の一覧」を別ページとして数える扱いです。
> 純粋なページ数だけ見たい場合は、GA4のレポートで `page_path` に `?` を含むものを除外してください。

## 2. 実装ファイル

| ファイル | 役割 |
| --- | --- |
| `app/_lib/analytics/index.ts` | イベント送信の共通関数。`NEXT_PUBLIC_GA_ID` 未設定なら何も送らない |
| `app/_components/GoogleAnalytics.tsx` | gtagの読み込み ＋ 遷移時の `page_view` 送信 |
| `app/_common/ui/TrackedButton.tsx` | クリックを計測するボタン |
| `app/_common/ui/TrackedLink.tsx` | クリックを計測するリンク（ボタン以外） |

**計測を追加したいときは** `app/_lib/analytics/index.ts` に関数を1つ足し、
`TrackedButton` / `TrackedLink` を使うか、クライアントコンポーネントから直接呼んでください。

### 環境変数

```bash
NEXT_PUBLIC_GA_ID=G-PWN1SW9F4E
```

- **未設定ならタグ自体を出力しません。** 開発中の自分のアクセスが混ざる心配はありません
- Vercelでは **Production環境にのみ設定してください**。Preview環境にも入れると、
  確認作業のアクセスが本番の数字に混ざります

## 3. GA4管理画面での設定（公開後に実施）

コード側の実装だけでは数字が意味を持ちません。以下は管理画面での作業です。

### 3-1. キーイベント（旧・コンバージョン）の設定 ★必須

1. GA4 →「管理」→「イベント」（データ表示 > イベント）
2. 公開後、実際に `line_add_friend_click` が記録されるのを待つ（最大24時間）
3. そのイベントの「キーイベントとしてマークを付ける」をON

これで「LINE追加が何件あったか」がレポートの主要指標になり、
流入元（検索／Instagram／TikTok）別のコンバージョン率が見られるようになります。

### 3-2. カスタムディメンションの登録 ★必須

**GA4は登録しないとカスタムパラメータをレポートで使えません。** 以下を登録してください。

「管理」→「カスタム定義」→「カスタムディメンションを作成」

| ディメンション名 | 範囲 | イベントパラメータ |
| --- | --- | --- |
| 導線の場所 | イベント | `link_location` |
| 犬種 | イベント | `breed` |
| 性別 | イベント | `sex` |
| ステータス | イベント | `status` |
| CTAラベル | イベント | `cta_label` |
| SNS | イベント | `social_network` |
| FAQ質問 | イベント | `faq_question` |

> 登録前に発生したイベントには**遡って適用されません**。公開直後に設定してください。
> 無料版の上限はイベントスコープ50個なので、7個なら余裕があります。

### 3-3. Search Console との連携

「管理」→「サービス間のリンク設定」→「Search Console のリンク」

これで「どの検索キーワードで来た人がLINE追加まで進んだか」が1つのレポートで見られます。
`docs/seo.md` のゴールA（犬舎名検索）の効果測定に直結します。

### 3-4. 内部トラフィックの除外

犬舎・制作側からのアクセスが数字に混ざらないようにします。

「管理」→「データストリーム」→ 対象ストリーム →「タグ設定を行う」→「内部トラフィックの定義」
に、犬舎のご自宅と事務所のIPアドレスを登録 → 「データフィルタ」で「内部トラフィック」を**有効**に。

> IPアドレスが変動する回線の場合は完全には防げません。その場合は
> ブラウザ拡張「Google アナリティクス オプトアウト アドオン」の導入をご検討ください。

### 3-5. データ保持期間

「管理」→「データ設定」→「データ保持」を **14か月** に変更（初期値は2か月）。
前年同月比を見るために必要です。

## 4. 公開後、最初に見るべきレポート

| 見たいこと | レポート |
| --- | --- |
| LINE追加が何件あったか | レポート →「エンゲージメント」→「イベント」→ `line_add_friend_click` |
| どのページからLINE追加されたか | 探索 → 自由形式 → 行:`link_location` 列:イベント数 |
| どの犬種が見られているか | 探索 → 自由形式 → 行:`breed` 指標:イベント数（`view_puppy_detail`で絞る） |
| どの犬種が探されているか | 同上を `filter_breed` で |
| 検索キーワード別の成果 | レポート →「集客」→「Search Console」 |

### 判断の目安

- 仔犬詳細を見た人のうち **LINE追加まで進む割合が5%を下回る** → 詳細ページの導線か情報量に問題
- `filter_breed` で多い犬種と `view_puppy_detail` で多い犬種が**食い違う** → 需要のある犬種の在庫が不足
- `faq_open` が特定の質問に偏る → その内容をFAQ以外の場所（仔犬詳細や見学ページ）にも出す
