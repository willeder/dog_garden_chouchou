## 1. プロジェクト概要

福岡県筑紫野市のブリーダー **Dog Garden Chouchou**（第一種動物取扱業登録 第4059100212号）の繁殖記録管理アプリ。

現在は Google スプレッドシートで台帳運用されており、それをスマートフォンで扱えるアプリに置き換える。**あわせて、法令上の帳簿と定期報告をこのアプリで完結させる。**

| 項目 | 内容 |
|---|---|
| 利用者 | 社内3名のみ |
| 端末 | **スマートフォン主体**（犬舎の現場で片手操作） |
| 扱う犬種 | TP=トイプードル / ML=マルチーズ / CI=チワワ / BFR=ビションフリーゼ |
| 現在の規模 | 母犬44頭（TP 11 / ML 14 / CI 19）＋ 種雄犬20頭前後 |
| 公開範囲 | 社内利用。**ただし公開フラグを立てた仔犬のみ公式サイトに出す** |

### 現行スプレッドシートの構造的問題

移行時に必ず遭遇します。**★印は実データで確認済みの具体例です。**

1. 1シートに TP/ML/CI の3ブロックが縦積みされ、**途中でヘッダー行が再登場する**
2. 交配履歴が「1回目〜6回目」の**横展開**（1回につき6列 × 6回 = 36列）
3. `61日　帝` のように**妊娠日数と分娩方法が1セルに混在**
4. `死1` のように**死産数が備考欄に埋もれている**
5. `ルイ　Ⅿ` のように種雄犬名にミックス判定記号が混入
6. 主キーがなく、**犬の識別が名前のみ**
7. 結合セル・空行が多数
8. ★**全角数字が混在**：ジョジョ4回目 `５８日　帝` / 5回目 `58日　帝`。カラー欄にも `ＢＫ` と `BK`
9. ★**出産日だけ空の行**：ジョジョ2回目（雄犬・日数・頭数はあるが出産日なし）
10. ★**同一内容の重複行**：ジョジョ4回目=5回目（2026/5/21）、クロミ4回目=5回目（2026/4/30）
11. ★**マイクロチップの表記が4パターン**：`392 149 002 433 081` / 先頭空白 / `392146 001 786 148` / `392149002175241`
12. ★**カラーが20種類近くあり、毛質（L/S）が混在**：`黒L` `茶S` `ブラックタンL` など
13. ★**台帳に無い犬が他シートに出る**：琥珀・ビビ・みるく・ひまわり・ムム・マム・うる・ぷぷ
14. ★**必須項目が全欠落の個体**：TP種雄「アル」（誕生日・体重・チップ・カラーすべて空）

## 2. ホームページとの関係

### 構成：同一プロジェクト・Supabase一本化

```
Next.js（1プロジェクト） ── Vercel
  ├─ 公開ページ（/, /puppies, /about …）  ← Supabase から匿名読み取り
  └─ /admin 配下（認証必須）              ← Supabase に読み書き

Supabase（1プロジェクト・Pro）
  ├─ Postgres（台帳・帳簿）
  ├─ Auth（マジックリンク・3名）
  └─ Storage（公開バケット / 非公開バケット）
```

### microCMS からの移行

現在、公式サイトは microCMS の `puppies` / `parents` / `voices` を参照しています。**一本化にあたり以下を行ってください。**

| API | 対応 |
|---|---|
| `puppies` | **廃止。** Supabase の `v_public_puppies` に置き換える |
| `parents` | **廃止。** `dogs`（`sire_id` / `dam_id`）に統合 |
| `voices` | **残す。** お客様の声は繁殖台帳と無関係で、microCMS のままが運用しやすい |

サイト側の改修範囲は `app/_api/puppies/` に閉じています。ここを Supabase 版に差し替えれば、ページ側のコードは変更不要です。**`app/_model/puppy.ts` の型を変えないこと**が移行を安く済ませるコツです。

### URL設計

```
/                     公開  トップページ
/puppies              公開  販売中の仔犬（Supabase の v_public_puppies から）
/puppies/[id]         公開  仔犬詳細
/about, /contact 等   公開  HPの各ページ
/login                公開  管理アプリのログイン
/admin                認証  犬一覧（管理アプリのホーム）
/admin/dogs/[id]      認証  犬カルテ
/admin/dogs/[id]/pedigree  認証  血統ツリー
/admin/litters/new    認証  出産記録の登録
/admin/puppies        認証  仔犬一覧
/admin/partners       認証  相手先管理
/admin/alerts         認証  今月のアラート（ワクチン・交配・仔犬検診）
/admin/ledger         認証  帳簿の閲覧・CSV出力
/admin/report         認証  定期報告（年度集計）
/admin/settings       認証  マスタ管理・データ書き出し
```

### 認証の境界（必須要件）

- `middleware.ts` で `/admin/*` を保護し、未認証は `/login` へリダイレクト
- `/admin/*` は **`noindex, nofollow` を必ず付与**（`robots.txt` と meta の両方）
- サイトマップに `/admin/*` を含めない
- HPのグローバルナビに管理アプリへのリンクを置かない
- **公開ページは `v_public_puppies` 以外を読まない。** `dogs` を直接 select しない

## 3. 技術スタック

| レイヤ | 採用 |
|---|---|
| フレームワーク | Next.js (App Router) + TypeScript |
| UI | Tailwind CSS + shadcn/ui |
| DB / 認証 / 画像 | **Supabase Pro（$25/月）** |
| 認証方式 | Supabase Auth **マジックリンク**（3名。パスワード管理を発生させない） |
| ホスティング | Vercel（契約済） |
| Supabaseクライアント | `@supabase/ssr` |
| CMS | microCMS（**`voices` のみ**） |

### Supabase Pro を選ぶ理由

容量ではありません。**Free は7日間DBリクエストが無いとプロジェクトが自動停止し、手動再開が必要**です。年末年始などで止まると誰も使えなくなります。加えて帳簿は5年保存義務があるため、日次バックアップは保険として妥当です。

## 4. スコープ

### 作るもの

- 犬の台帳（繁殖犬・仔犬を統合管理）
- 交配・出産記録
- 血統ツリー（3世代）
- ワクチン接種日の記録
- 仔犬の識別（毛色＋毛質＋紐の色）
- 販売・顧客・引渡し管理
- **【法令】帳簿の記録と出力（13項目・5年保存）**
- **【法令】定期報告の年度集計（①＋②−③＝④）**
- **公式サイトへの公開連携（公開フラグ＋公開専用ビュー）**
- **アラート（ワクチン次回予定・交配可能時期・仔犬検診の当月対象を一覧表示）**
- 現行スプレッドシートからのデータ移行

### 作らないもの

| 項目 | 理由 |
|---|---|
| **プッシュ通知・メール通知・LINE連携** | 毎日アプリを開いて確認する運用のため不要 |
| **アラートの「送信」** | アラート画面を毎日開いて確認する運用。プッシュもメールも送らない |
| **定期実行（pg_cron / Edge Functions）** | 同上 |
| **仔犬の毎日の体重・哺乳記録** | 毎日は測らないため |
| **オフライン対応** | 犬舎内は電波が届く前提 |

> ネット上には LINE Notify を使った通知実装の記事が大量に残っていますが、**LINE Notify は 2025年3月31日でサービス終了済み**です。

### v1 からのスキーマ変更点

| 変更 | 理由 |
|---|---|
| **`coat_types` テーブルを新設** | 台帳の `黒L` `茶S` の L/S はロング／スムースコート。毛色と別の軸なので分離しないとマスタが破綻する |
| `dogs.coat_type_code` を追加 | 同上 |
| **`dogs.acquired_on` / `died_on` / `death_cause`** | 【法令】帳簿の必須項目。定期報告の②③の集計にも必須 |
| **`dogs.breeder_id` を `supplier_id` と分離** | 台帳でも「繁殖者」と「仕入れ元」は別列。法令上も別項目 |
| **`partners.license_no`** | 【法令】繁殖者の登録番号 |
| **`sales.staff_name` / `explained_in_person` / `explained_on` / `compliance_checked`** | 【法令】帳簿の必須項目 |
| **`deleted_at` を全テーブルに追加** | 【法令】5年保存のため物理削除しない |
| **`on delete cascade` → `restrict`** | 犬を消すとワクチン履歴ごと消えるのを防ぐ |
| **`microchip` に `^[0-9]{15}$` の制約** | 数字のみで保存し、表示時に整形。これで下4桁検索が確実に動く |
| **`litters` に `(dam_id, birth_date)` の部分一意索引** | 移行時の重複行を機械的に弾く |
| **`is_mix` が父未登録時に NULL を返す** | v1の式では父が NULL のとき `true`（＝ミックス）になる不具合があった |
| **`dogs.is_published` / `public_photo_path`** | 公式サイト連携 |
| **`v_public_puppies`** | 公開してよい列だけを露出 |
| **`fn_annual_report(fy)`** | 【法令】定期報告の年度集計 |
| **`v_ledger`** | 【法令】帳簿13項目の出力 |
| **`fn_pedigree(root, max_gen)`** | 血統ツリー。循環参照ガードを関数側に持たせた |
| **`updated_by` を主要テーブルに追加** | 3名が同じデータを触るため。誰が変えたかを追える |
| **`vaccine_schedules` テーブルを新設** | ワクチンの接種間隔を設定で持つ。運用が変わってもコード修正なしで直せる |
| **`v_vaccine_due`** | 犬×種別ごとの最終接種日と次回予定日 |
| **`fn_monthly_alerts(月, 未接種を含めるか)`** | 当月のアラート。既定では未接種を含めない（移行直後に大量に出て当月分が埋もれるため） |
| **全ビューを `security_invoker = on` に** | PostgreSQL 15+ のビューは既定で作成者権限になり **RLS を迂回する**。Supabase の診断でも ERROR 判定 |
| **匿名ロールから内部ビューの権限を剥奪** | Supabase は public スキーマに自動で権限を付与するため、**剥奪しないと `v_ledger` が公開キーで読めてしまう** |
| **関数に `search_path` を固定** | 検索パス乗っ取りの防止 |
| **外部キーに覆いインデックスを追加** | 親行の更新・削除時の全走査を防ぐ |
| `breeds.hex` を追加 | 犬種色をコードに散らさずマスタで持つ |

### 計算値（すべて入力欄を作らない）

| 項目 | 算出方法 | 検証状況 |
|---|---|---|
| 仔犬検診日 | 出産日 + 49日（生成列） | 実データ全件で一致を確認済み |
| 次回交配可能月 | 最新出産日 + 5ヶ月の月初 | 実データ全件で一致を確認済み |
| ミックス判定 | 父と母の `breed_code` が異なる。**父が未登録なら NULL（判定不能）** | 実データで例外なしを確認済み |
| ワクチン接種回数 | 接種日レコードの件数 | — |
| ワクチン次回予定日 | 最終接種日 + `vaccine_schedules.interval_months`（既定12ヶ月） | **要確認**（第11章9項） |
| 当月のアラート | `fn_monthly_alerts(月初日)` | 実データの2026年8月分と照合済み |
| 帳簿・定期報告 | `v_ledger` / `fn_annual_report()` | ①＋②−③＝④ の一致を確認済み |

### Storage 設計（必ずバケットを分ける）

| バケット | 公開設定 | 用途 |
|---|---|---|
| `dogs-private` | **非公開** | 台帳用の写真。署名付きURLでのみ配信 |
| `dogs-public` | 公開 | 公式サイトに出す写真のみ |

**同一バケットで公開制御しないこと。** URLが1つ漏れた時点で全件見えます。公開フラグを立てたときに、非公開バケットから公開バケットへコピーする実装にしてください。

### RLS

`schema.sql` に含まれています。要点は2つです。

- `authenticated`（社内3名）は全テーブル全件読み書き可
- `anon`（公式サイト）は `dogs` のうち **`is_published = true` かつ `status in ('在舎','商談中')` かつ未削除** の行だけ `select` 可。実際の読み出しは `v_public_puppies` 経由に限定する

**Supabase 固有の落とし穴が2つあります。`schema.sql` の第12節で対処済みですが、ビューを追加する際は毎回同じ対応が必要です。**

1. **ビューは既定で RLS を迂回する。** PostgreSQL 15以降、ビューは作成者の権限で動くため、`security_invoker = on` を明示しないと閲覧者のRLSが効きません
2. **Supabase は `public` スキーマの全テーブル・ビューに `anon` / `authenticated` の権限を自動付与する。** 内部ビューは明示的に `revoke` しないと、**公開キーだけで帳簿（マイクロチップ・顧客名・価格）が読めてしまいます**

ビューを追加したら必ず Supabase の Security Advisor を実行し、指摘0件を確認してください。

## 6. 画面仕様

### 6-1. 情報設計

```
/login  マジックリンク
   │
   └─ /admin  下部固定タブ（4つ）
       ├─ 犬       … 繁殖犬の一覧（ログイン後の初期画面）
       │   └─ 犬カルテ … 基本 / 出産 / 血統 / ワクチン
       ├─ 仔犬     … 販売前の仔犬（dogs の絞り込みビュー）
       │   └─ 仔犬カルテ … 基本 / 血統 / ワクチン / 販売 / 公開
       ├─ アラート … 今月の対象（ワクチン・交配・仔犬検診）
       └─ その他   … 相手先 / 帳簿 / 定期報告 / 設定
```

タブは4つまで。5つ以上にすると押し間違えが増えます。

### 6-2. 犬一覧（/admin）

- 犬種タブ: すべて / TP / ML / CI / BFR（横スクロール）
- 絞り込みチップ: ♀母犬 / ♂種雄犬 / 退役
- 検索: 名前とマイクロチップの部分一致。**下4桁での検索に必ず対応すること**（現場ではチップ番号の下4桁で照合する）
- カード左端に**犬種カラーの縦バー**（`breeds.hex`）
- 表示項目: 名前 / 性別 / 誕生日 / 毛色・毛質 / 体重 / 出産回数 / 最新出産日

### 6-3. 犬カルテ（/admin/dogs/[id]）

タブ: 基本 / 出産 / 血統 / ワクチン

**「出産」タブ** — 現行台帳の横36列を縦タイムラインに置換する

```
出産 4回                    ＋ 記録を追加
次回交配可能  2026年11月〜       ← 表示のみ。強調・警告なし

④ 2026/06/07
   父 エルメス
   62日 自然分娩
   ♂●  ♀●●   死産 ●
   仔犬検診 2026/07/26

③ 2025/11/08
   父 エルメス
   60日 自然分娩
   ♂●
```

頭数を**点（●）の並び**で表す。産子数の推移が一目で読め、回数の上限も消える。死産は `--danger` 色の点で区別する。

**「ワクチン」タブ**
- `v_vaccination_counts` から「混合 2回接種済み」を表示
- 接種日を新しい順に一覧。各行に古い順の連番で「1回目」「2回目」を表示
- `v_vaccine_due.next_due_on` から**次回予定日を表示する**（例: 次回 2027/07/18）
- 期限を過ぎている場合は「期限超過」と添える。**回数は手入力させない**

**「基本」タブ** — 帳簿項目も含める
- 写真、毛色、毛質、体重、マイクロチップ、遺伝子、繁殖者、仕入れ元、状態
- **所有日**、（死亡している場合のみ）**死亡日・死亡原因**

### 6-4. 出産記録の登録（/admin/litters/new）

```
出産日      [2026/08/16    ]
父          [検索して選択  ▾]   ← 既存 dogs から選択。テキスト手入力は不可
妊娠日数    [ 61 ] 日
分娩方法    [自然][帝王切開][後帝]

♂  [－] 3 [＋]                  ← タップで増減。数値キーボードを出さない
♀  [－] 1 [＋]
死産[－] 0 [＋]

備考        [              ]
          [ 保存 ]
```

- **父をテキスト手入力させない。** 許すと現行台帳と同じ表記ゆれが再発する
- 妊娠日数が 50〜75 の範囲外なら警告（保存はブロックしない）
- 仔犬検診日・次回交配可能月・ミックス判定の入力欄は作らない
- **同じ母犬・同じ出産日が既にある場合は保存前に確認**（DB側にも部分一意索引あり）

**保存後の追加処理**
- 「産まれた仔犬を登録しますか？」と確認し、はいなら ♂数＋♀数ぶんの `dogs` レコードを下書き生成
- 自動で埋める: `birthday` / `sire_id` / `dam_id` / `litter_id` / `breed_code`（母の犬種を既定）/ `acquired_on`（=出産日）/ `status='在舎'` / `is_self_bred=true`
- 名前は「クッキー ④ ♂1」のような仮名で生成し、後から変更可

### 6-5. 仔犬一覧（/admin/puppies）

**`puppies` テーブルは作らない。** `dogs` に対する絞り込み。

```sql
where litter_id is not null
  and deleted_at is null
  and status in ('在舎','商談中','売約','引渡済')
```

- ステータスタブ: 在舎 / 商談中 / 売約 / 引渡済
- 表示: 名前の左に**毛色の丸バッジ** / 性別 / 毛色名・毛質名 / 混合ワクチン回数 / **公開中バッジ**

### 6-6. 仔犬の識別（重要）

同じ腹の仔犬は**母・父・誕生日・犬種がすべて同じ**で、違うのは性別と毛色だけ。

さらに**同じ毛色・同じ性別が複数いる場合、犬舎では実際に仔犬へ色の違う紐を着けて区別している。** アプリはこの運用をそのまま写す。**連番（①②）は使わない**（画面上の①が現場のどの子か分からないため）。

**表示ルール**
- 丸の**内側** = 毛色（`coat_colors.hex`。`hex2` があれば左右半分ずつ塗り分ける）
- 丸の**外周** = 紐の色（`ribbon_colors.hex` の輪を重ねる）
- 紐を着けていない個体には輪を描かない
- 淡色（ホワイト等）は丸に細い輪郭線を付ける
- **色だけに頼らず、毛色名・毛質名・紐の色名を必ず文字でも併記する**
- `status` が `'在籍'` または `'引渡済'` の個体には紐の輪を描かない

**入力ルール**
- 紐の色は**自動割り当てしない。** ユーザーが実物に合わせて選ぶ
- 同じ `litter_id` 内に同じ `color_code` かつ同じ `sex` が2頭以上いる場合のみ、「紐の色を設定してください」と促す
- 同じ `litter_id` 内で紐の色が重複したら警告を出す

### 6-7. 仔犬カルテ

タブ: 基本 / 血統 / ワクチン / 販売 / 公開

- 「ワクチン」タブで接種日を追加・削除（種別は 混合 / 狂犬病）。回数は入力させず件数から自動表示
- **一腹の仔犬に同じ接種日をまとめて登録できること**（現場では同日に全頭接種する）
- 「販売」タブで `sales` レコードを作成。**帳簿項目（販売担当者名・対面説明の実施と日付・引渡し先の法令違反確認）を必ず入力させる**
- **「公開」タブ**：公式サイトに出すかのトグル、公開用写真の選択、公開時のプレビュー
- 画面上部に**「繁殖犬にする」ボタン**。押すと `status` を `'在籍'` に変更（自家保留。データの移し替えは発生しない）

### 6-8. 血統ツリー（/admin/dogs/[id]/pedigree）

- `fn_pedigree(dog_id, 3)` を呼ぶだけ。循環参照ガードは関数内で済んでいる
- 不明な親は `?` と表示し、**データがないことを隠さない**
- ノードタップでそのカルテへ遷移
- 横スクロール可能。スマホで3世代が破綻せず読めること

### 6-9. アラート（/admin/alerts）※v2で追加

現行スプレッドシートの「今月のアラート一覧」に相当します。**画面で見るだけ。通知は送りません。**

## 7. デザイン方針

### コンセプト

**「毎日ひらいても苦にならない台帳」**

施主からの要望は「とにかく使いやすく、日頃から使いたくなること」です。装飾で好感度を上げるのではなく、**操作が速く、迷わず、失敗しないこと**で「使いたくなる」状態を作ります。

### 使いやすさの定義（実装時に測れる形にする）

| 指標 | 目標 |
|---|---|
| 犬を探す | ログインから目的の犬のカルテまで **3タップ以内** |
| 出産を記録する | 母犬選択から保存まで **1画面・キーボード入力ゼロ** |
| ワクチンを記録する | カルテを開いてから **2タップ**で日付追加 |
| 迷いを消す | 1画面につき主要な操作は1つ。ボタンを並べない |
| 待たせない | 一覧の初期表示は **1秒以内**。ページネーションではなく無限スクロール |

### 「使いたくなる」ための具体策

装飾ではなく、**気持ちよさを生む仕掛け**として以下を入れます。

1. **犬の顔が見える一覧にする**
   写真をサムネイルで出す。台帳が「データの羅列」ではなく「うちの子たちの一覧」に見えることが、毎日開く動機になります。写真未登録の個体は毛色の丸で代替します

2. **入力を「選ぶ」に寄せる**
   頭数はステッパー、分娩方法はセグメント、父は検索選択。**キーボードが立ち上がる回数を減らすほど、現場での入力が続きます**

3. **保存に手応えを出す**
   保存ボタンを押したら即座に結果を返し、成功したことが一目で分かる表示を出す。**確認ダイアログを挟まない**（取り消せる設計にして、確認をなくす方が速い）

4. **入れたことが積み上がって見える**
   カルテに「出産4回」「混合2回接種済み」と件数を出す。記録が増えるほど画面が充実するので、入力の動機になります

5. **失敗させない**
   父はテキスト入力させない、重複出産日は保存前に確認、妊娠日数の範囲外は警告する。**入力ミスで台帳が汚れないこと**が、長期的な使いやすさそのものです

6. **戻れる**
   削除は論理削除なので、誤操作は取り消せます。**「取り消しました」を出せる設計にすること**

### デザイントークン

ブランド色に縛られず、**現場で読めること**を基準に決めています。公式サイトのトンマナ（ピンク・ベージュ）は明度が高く、屋外・逆光では文字が沈むため採用しません。

```css
--paper:      #F5F5F2;  /* 背景。純白より目が疲れない */
--surface:    #FFFFFF;  /* カード */
--ink:        #1A1C1A;  /* 本文。純黒を避ける */
--ink-muted:  #6B6F6B;  /* ラベル・補助テキスト */
--rule:       #DEDFD9;  /* 罫線 */
--action:     #2F6B4F;  /* 操作色。緑は「進む」の意味が伝わりやすい */
--danger:     #A8322D;  /* 死産・退役・削除 */

/* 犬種色（犬一覧の左端の縦バー。breeds.hex と同値） */
--breed-tp:  #C98A2E;
--breed-ml:  #8A93A0;
--breed-ci:  #8B5E3C;
--breed-bfr: #5E7C6B;
```

`--action` と `--paper` のコントラスト比は 5.9:1 で、WCAG AA（4.5:1）を満たします。屋外での可読性はここで担保します。

### 色分けのルール

| 画面 | 形 | 意味 |
|---|---|---|
| 犬一覧 | 左端の**縦バー** | 犬種 |
| 仔犬一覧・仔犬カルテ | 名前の左の**丸** | 毛色（＋外周の輪で紐の色） |

**形を変えることで意味の違いを伝える。** 同じ縦バーで画面ごとに意味が変わると必ず混乱します。

**色は情報にのみ使い、装飾に使わない。**

### タイポグラフィ

| 役割 | フォント |
|---|---|
| 本文・見出し | Zen Kaku Gothic New |
| 数値・日付 | JetBrains Mono（**差し替え不可**） |

**日付・妊娠日数・頭数・マイクロチップ番号はすべて等幅にする。** 桁が揃うことで履歴を縦に並べたときに差が視覚的に読み取れ、チップ番号（`392 149 002 083 297`）の照合でも桁ずれが起きません。これは装飾ではなく機能要件です。

### レイアウト規則

- タップ領域は最小 **44 × 44px**
- 犬名は 20px / 600。一覧でも省略しない
- 1画面1目的。カルテはタブで分割し縦スクロールを深くしない
- 入力フォームは全項目を1画面に置く（ステップ分割しない）
- 主要な操作ボタンは**親指が届く下部**に置く（上部に置かない）

### Phase 2: データ移行（最重要）

**同梱の `migration/` に、実装済み・検証済みの一式があります。**

| ファイル | 内容 |
|---|---|
| `migration/README.md` | 手順書。**まずこれを読む** |
| `migration/gas_export.gs` | スプレッドシート → CSV の Google Apps Script |
| `migration/import.sql` | CSV → Supabase の投入スクリプト（名前をUUIDに解決） |
| `migration/verify_import.sql` | 投入後の検証。取りこぼし・データ品質を0件で確認 |

パーサは実データの値で自動テスト済みです（33件・全パス）。
「５８日　帝」（全角）「死1　剥離」「ルイ　Ⅿ」「392146 001 786 148」「黒L」などが
すべて正しく分解されること、既知の異常（ジョジョ2回目の出産日なし、
ジョジョ／クロミの重複行、モモ3回目の「59日♀5」）が要確認リストに出ることを確認しています。

**着手前に `SIRE_BREED`（種雄犬の名前→犬種の対応）を実物と突き合わせて修正してください。**
種雄犬台帳には犬種の列が無いため、ここを誤るとミックス判定が丸ごと狂います。

以下は、上記を使わずゼロから作る場合の指示です。

```
Phase 2: 既存 Google スプレッドシートからのデータ移行。

移行元の構造上の問題:
- 1シートに TP/ML/CI の3ブロックが縦積みされ、途中でヘッダー行が再登場する
- 交配履歴が「1回目〜6回目」の横展開（1回につき6列 × 6回 = 36列）
- 「61日　帝」のように妊娠日数と分娩方法が1セルに混在
- 「死1」のように死産数が備考欄に埋もれている
- 「ルイ　Ⅿ」のように種雄犬名にミックス判定記号が付く
- 主キーがなく、犬の識別が名前のみ
- 結合セル・空行が多数

変換ルール:
- 【必須】全セルを最初に NFKC 正規化する（全角→半角）。
  「５８日　帝」のような全角数字が実在するため、これをしないと変換が壊れる
- 「◯◯日　帝」   → gestation_days=◯◯, method='帝王切開'
- 「◯◯日　後帝」 → gestation_days=◯◯, method='後帝'
- 「◯◯日」のみ   → gestation_days=◯◯, method='自然'
- 「帝」のみ（日数なし） → gestation_days=NULL, method='帝王切開'
- 備考の「死N」   → stillborn_count=N（備考からは除去）
- 種雄犬名末尾の「　Ⅿ」は除去する（DBに保存しない。ビューで自動算出）
- 【必須】マイクロチップは数字のみを残して15桁で保存する
  （regexp_replace(v, '\D', '', 'g')）。空欄は空文字ではなく NULL を入れる
- 【必須】カラー欄の末尾「L」「S」は毛質として coat_type_code に分離し、
  残りを毛色として color_code に正規化する。原文は color にそのまま保持する
- 親の表記（例:「クッキー・サンダー」）は breeder_note に原文保持し、
  名前が dogs に一致する場合のみ sire_id / dam_id を解決する
- 繁殖者が「自家繁殖」の犬は is_self_bred = true
- acquired_on は、自家繁殖なら birthday、仕入れなら空欄のまま要確認リストへ

出力してほしいもの:
1. スプレッドシートを読んで CSV に変換する Google Apps Script
2. 「要確認リスト」を別途出力すること。以下を必ず含める:
   - 変換できなかった行
   - 母犬が dogs に存在しない出産記録
   - 出産日が空で他の項目だけ埋まっている行（ジョジョ2回目に実在）
   - 同一母犬・同一出産日の重複行（ジョジョ4=5回目、クロミ4=5回目に実在）
   - 犬種が判定できない行
   - 同名の犬が複数いるケース
   - 必須項目が全欠落の個体（TP種雄「アル」に実在）
   - acquired_on が埋まらなかった個体（法令の帳簿項目のため）
3. 移行前後の件数照合レポート（犬の頭数、出産記録の件数、合計産子数）
4. カラー欄と毛質の値の集計（何種類あるか。グルーピングの判断に使う）

既知の不整合: 「琥珀」「ビビ」「みるく」「ひまわり」「ムム」「マム」「うる」「ぷぷ」が
他シートに登場するが母犬台帳に登録がない。同種の不整合を必ず検出して報告すること。
```

### 補足：ワクチン間隔について（11-9）

既定値（前回接種日 + 12ヶ月）で 2026年8月のアラートを算出したところ、**現行スプレッドシートでは「対象なし」なのに、本実装では「スフレ（TP・混合 2025/08/06 接種）」が対象に出ます。**

考えられる理由は2つです。

1. スプレッドシートのアラート数式が一部の犬種（CI）しか参照していない
2. 接種間隔が12ヶ月ではない、または対象外とする条件がある

**運用開始前に、実際の接種間隔を施主に確認してください。** `vaccine_schedules.interval_months` を直すだけで対応できます。

なお交配可能時期（ポコ／ジュジュ／ラン）と仔犬検診については、スプレッドシートの結果と**完全に一致**しました。
