# データ移行手順（Phase 2）

現行の Google スプレッドシートから Supabase へ移す手順です。
**Phase 2 が全体の成否を決めます。件数照合と要確認リストの目視を省略しないでください。**

---

## 手順

### 1. CSVを書き出す

**方法A: Python（推奨。Google側の都合に左右されない）**

1. スプレッドシートを **ファイル → ダウンロード → Microsoft Excel (.xlsx)** で保存
2. `pip install openpyxl`
3. `python3 convert.py ダウンロードしたファイル.xlsx`

**方法B: Google Apps Script**

1. スプレッドシートを開く → **拡張機能 → Apps Script**
2. `gas_export.gs` の内容を貼り付けて保存
3. 関数 `run` を実行（初回は権限の承認が必要）

> Apps Script の初回実行時に
> **「Cloud Platform プロジェクトの作成中に予期しないエラーが発生しました。エラーコード: INTERNAL」**
> が出ることがあります。Google側で既定のGCPプロジェクトを自動作成できないときに発生します。
> 時間をおいて再試行するか、Workspace管理者にCloud Platformプロジェクトの作成権限を確認してください。
> **方法Aを使えばこの問題は回避できます。** 出力されるCSVは方法Bとまったく同じです。

どちらの方法でも、以下が書き出されます。

| ファイル | 内容 |
|---|---|
| `dogs.csv` | 犬（母犬＋種雄犬）。**仔犬は含みません** |
| `litters.csv` | 出産記録。横36列を1回1行に開いたもの |
| `vaccinations.csv` | ワクチン接種日 |
| `partners.csv` | 仕入れ元・繁殖者。`license_no` は空なので後で埋める |
| **`review.csv`** | **★要確認リスト。必ず目視すること** |
| `summary.csv` | 件数照合レポート＋カラー／毛質の出現数 |
| `sire_breeds.csv` | 種雄犬の犬種の判定結果と根拠 |

### 種雄犬の犬種について（手作業はほぼ不要）

種雄犬の台帳には犬種の列がありません。**スクリプトが交配記録から自動で推定します。**

台帳の「雄犬」欄に付く **「Ⅿ」＝ミックス**（父と母の犬種が違う）という記号が手がかりです。

```
Ⅿが付かない交配が1件でもある → その母犬と同じ犬種（確定）
Ⅿ付きの交配しかない          → その犬種ではない（消去法で絞る）
交配記録が1件も無い           → 推定できない
```

判定できなかった犬だけ `SIRE_BREED_OVERRIDE`（スクリプト冒頭）に書いて再実行してください。
判定の根拠は `sire_breeds.csv` に全件出るので、**確定分も念のため目視してください。**

### 2. review.csv を潰す

**ここを飛ばすと、不整合を抱えたまま本番が始まります。**

検出される種別と対処:

| 種別 | 対処 |
|---|---|
| 犬種が不明 | スプレッドシート側を直すか、手で犬種を補う |
| 種雄犬の犬種を判定できない | `SIRE_BREED_OVERRIDE` に追記して再実行 |
| 同名の個体を区別する符号 | 「プラダ①」のような丸数字。同名の種雄犬が複数いるため、どの個体かを特定する |
| **出産日が空** | 実在します（ジョジョ2回目）。**出産日が無いと登録できません。**日付を調べて補う |
| **同一出産日の重複** | 実在します（ジョジョ4=5回目、クロミ4=5回目）。**機械的に消さないこと。**同日2回の出産か入力ミスかを確認する |
| マイクロチップの桁数 | 15桁でないものを列挙。台帳の入力ミスか、そもそも未登録か |
| 毛色を正規化できない | `COLOR_MAP` に追記して再実行（例:「牛」） |
| 妊娠日数が範囲外 | 50〜75日から外れるもの |
| 妊娠日数欄に余分な文字 | 実在します（モモ3回目「59日♀5」）。頭数欄に入れ直す |
| 必須項目がほぼ空 | 実在します（種雄「アル」）。帳簿の必須項目なので埋める |
| 所有日を確定できない | 仕入れ元が不明で `acquired_on` が空。**法令の帳簿項目です** |
| 同名の犬 | 血統の紐付けが誤ります。どちらかを改名するか、手で対応付ける |
| **同名のため改名** | 同名だが誕生日が違う＝別個体。「ハリー（退役）」のように改名して取り込みます |
| **重複行** | 同名かつ同じ誕生日＝台帳の行が二重。1頭に統合済み（ダンヒル） |
| **マイクロチップの重複** | `dogs.microchip` は重複禁止。**直さないと投入が落ちます**（プラダ） |
| **★父を紐付けできない出産記録** | 父が犬の台帳に無い。父を空欄にし、名前を備考へ逃がします |
| **★種雄犬の犬種が決まらない** | `SIRE_BREED_OVERRIDE` に追記して再実行 |
| 施主確認により補完／削除 | `LITTER_FIXES` による修正。反映されたことの確認用 |
| 分娩方法が分からない | 妊娠日数欄が空で 自然／帝王切開 を判定できない |

### 3. summary.csv で件数を照合する

| 確認項目 | 期待値 | 根拠 |
|---|---|---|
| TP ♀ / TP ♂ | 11 / 6 | ♂は外交配1頭を含む |
| ML ♀ / ML ♂ | 14 / 6 | 同上 |
| CI ♀ / CI ♂ | 26 / 16 | ♂は退役8頭を含む |
| BFR ♀ / BFR ♂ | 4 / 2 | ♂は外交配1頭を含む |
| PO ♂ | 1 | ウルフ |
| 犬 合計 | 86 | うち外交配の♂3頭 |
| 出産記録 | 91 | |
| 産子数 合計（♂＋♀） | 267 | |
| 死産 合計 | 18 | |
| ワクチン記録 | 142 | |
| 帳簿（`v_ledger`）の行数 | 83 | 86 − 外交配3。**外交配は自舎の所有ではない** |

> **連番の無い行は取り込みません。** 台帳には過去の犬・参考記録が連番なしで残っており、
> 犬種欄だけで数えると BFR ♀ が 23頭 に膨らみます。正式な頭数は A列の連番で決まります。
> 除外した行は `excluded.csv` に全件出るので、消してよい行か目視してください。
>
> ただし**♂シートの連番なしの行は「引退した種雄犬」**で、過去の出産記録の父として
> 参照されます。`status='退役'` で取り込むので、通常の一覧には出ませんが
> 血統と帳簿のために残ります。

### 外交配（他犬舎から借りた種雄犬）

歌舞伎（ML）・ハーレ（BFR）・アル（TP）は他犬舎の♂です。
交配記録の父としては必要ですが、**自舎の所有ではないので法令上の頭数には入りません。**

`dogs.is_external = true` を立てることで、以下から自動的に外れます。

- `v_ledger`（帳簿13項目）
- `fn_annual_report()`（定期報告の ①期首＋②増加−③減少＝④期末）

誕生日・マイクロチップ・所有日は他犬舎の情報なので空のままで構いません。

### 4. Supabase へ投入する

CSVは**名前**で親子を参照しています（`dam_name` / `sire_name` / `supplier_name`）。
Supabase 側で UUID に解決する必要があるため、以下の順で流します。

```
1. partners.csv     → partners
2. dogs.csv         → dogs        （breeder_name / supplier_name を partners.id に解決）
3. litters.csv      → litters     （dam_name / sire_name を dogs.id に解決）
4. vaccinations.csv → vaccinations（dog_name を dogs.id に解決）
```

`import.sql` に、一時テーブル経由で名前をUUIDに解決する投入スクリプトを用意しています。

### 5. 投入後の検証

`verify_import.sql` を実行し、「現在」と「期待値」が一致することを確認します。
②の取りこぼしは**すべて0件**が期待値です。

③のデータ品質は、移行直後は0になりません。以下は台帳側に元データが無いためで、
運用開始前に手で埋める必要があります。

| 項目 | 移行直後 | 内容 |
|---|---|---|
| 所有日が空の犬 | 44 | 仕入れ41＋外交配3。台帳に取得日の記録が無い。**法令の帳簿項目** |
| マイクロチップ未登録 | 5 | つばさ・プラダ（退役）・外交配3頭 |
| 誕生日が空 | 3 | 外交配3頭。他犬舎の犬なので不明 |
| 分娩方法が空 | 1 | テテ 2023-08-31（出産日が誤りとのことで確認待ち） |

**自家繁殖の42頭は `acquired_on = birthday` が全頭入っています**（検証済み・漏れ0件）。
埋める必要があるのは仕入れた41頭だけです。

## 施主確認の反映（2026-08-16）

スクリプト冒頭の定数に、確認結果を根拠つきで書いてあります。
台帳を直接書き換えていないので、**何を変えたかは常に追えます。**

| 定数 | 内容 |
|---|---|
| `SIRE_BLOCK_BREED` | ♂シートの連番ブロック → 犬種。1=CI / 2=TP / 3=ML / 4=BFR / 5=PO |
| `SIRE_BREED_OVERRIDE` | 個体単位の指定。ハリー2頭の区別、退役チワワ8頭 |
| `DOG_DROP` | 在籍していない犬（アル）。`excluded.csv` に理由つきで残る |
| `EXTERNAL_SIRES` | 外交配の♂3頭（歌舞伎・ハーレ・アル）。`is_external=true` で登録 |
| `LITTER_FIXES` | ジョジョ2回目の出産日補完、ジョジョ／クロミ5回目の削除、ぽにょ2件の分娩方法 |
| `COLOR_MAP` | 「牛」→ BKW（白黒）、「CR H」→ CHLTW（チョコ白） |

`PO`（ポメラニアン）と `CHLTW`（チョコホワイト）は
マイグレーション `add_pomeranian_breed_and_choco_white_color` で追加済みです。

## 検証済みの変換

パーサは実データの値で自動テストしています（33件・全パス）。

```
「61日　帝」      → 61日 / 帝王切開
「５８日　帝」全角 → 58日 / 帝王切開      ← NFKC正規化が効いている
「61日　後帝」    → 61日 / 後帝
「帝」のみ        → 日数なし / 帝王切開
「59日♀5」        → 59日 / 自然 ＋ 要確認「♀5」
「死1　剥離」     → 死産1 ＋ 備考「剥離」
「ルイ　Ⅿ」       → ルイ（Ⅿ を除去）
「392146 001 786 148」→ 392146001786148（15桁）
「黒L」           → 毛色BK ＋ 毛質L
「ＢＫ」全角       → BK
「プラダ①」       → プラダ（丸数字を除去し、要確認に回す）
```

実データ4頭ぶんの交配履歴を通した結合テストでも、既知の異常
（ジョジョ2回目の出産日なし・ジョジョ/クロミの重複行・モモ3回目の余分な文字）を
すべて検出できることを確認しています。

さらに **PostgreSQL 16 に `schema.sql` を流し、生成された4つのCSVを `import.sql` で
実際に投入するところまで通しで検証済み**です（2026-08-16）。

```
staging  partners 20 / dogs 86 / litters 91 / vaccinations 142
INSERT   20 / 86 / 91 / 142   ← 1件も落ちない
verify   ①件数照合   すべて期待値と一致
         ②取りこぼし すべて0件
         ④法令       外交配の♂は帳簿に出ない（0件）／帳簿83行
```

外部キー違反・一意制約違反・型エラーはいずれも0件です。

## 注意

- **仔犬は移行しません。** 現行台帳に仔犬の個体データが無いためです。運用開始後、出産記録から下書き生成されます
- **`acquired_on`（所有日）は自家繁殖の犬しか自動で埋まりません。** 仕入れた犬は台帳に取得日の記録が無いため、運用開始前に手作業で埋める必要があります。法令の帳簿項目です
- **血統（`sire_id` / `dam_id`）は名前一致でのみ解決します。** 台帳の「クッキー・サンダー」のような血統表記は `breeder_note` に原文のまま保持し、自動では解決しません
